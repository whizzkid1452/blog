### 1. 개요 및 배경 (Context)

- 개발 에이전트가 오래된 브라우저 우회 코드를 반복해서 제안하지 않도록 Modern Web Guidance를 로컬 작업에 적용하는 방법을 검토함.
- 도구를 설치할 위치는 어떤 코드가 브라우저에서 실행되는지, 폴리필 추가 여부는 어떤 브라우저를 지원하는지에 따라 판단해야 했음.

### 2. 핵심 내용 / 문제 해결 과정 (Core / Troubleshooting)

- Node.js 서버 저장소와 Vue 웹 저장소를 나눠 확인함. 브라우저 호환성만 검토한다면 웹 저장소에 가이드를 두는 편이 적용 범위를 읽기 쉬움. 공통 규칙으로 연결하면 여러 저장소에서 재사용할 수 있고, 웹 작업일 때만 활성화할 조건과 에디터별 발견 방식을 맞춰야 함.
- **개발 도구와 브라우저 실행 코드**의 역할을 나눔. 검사 규칙은 지원 목록과 API 사용을 개발 중 확인하게 돕지만, 브라우저 기능을 새로 제공하지는 않음. **폴리필**은 지원 대상에 빠진 기능을 메우기 위해 제품에 포함하는 코드이며, 실제 브라우저 동작과 전달 코드가 달라짐.
- 프로젝트 범위 도입을 먼저 제안했고, 후속 대화에서 공통 로컬 규칙의 진입점과 Cursor의 조건부 적용도 확인함. 이 작업은 도구 및 규칙 경로를 검토한 것이며 브라우저 호환성이 개선됐다는 측정은 없었음.

### 3. 인사이트 및 적용점 (Takeaway & Next Action)

- 새 API를 사용할 때는 **지원 브라우저 목록 → 기능 지원 여부 → 필요한 폴리필 또는 대체 동작** 순서로 판단할 수 있음. 개발 도구를 추가하는 결정과 브라우저로 보내는 코드를 바꾸는 결정은 각각 근거가 필요함.
- 공통 규칙 적용을 검증하려면 새 채팅에서 규칙이 읽히는지 확인하고, 실제 제품 호환성은 지원 대상 브라우저에서 별도로 살펴야 함.
