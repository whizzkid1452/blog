## Q. 미디어 제작 도구의 작업 진행 상황을 설명해 주세요.

A. 이날 오전에 확인한 상태는 Mac 로컬 제작 기능과 코드 구조 정리가 반영된 상태였어요. 원본 네 종류로 결과물 다섯 종류를 만들고 검사하는 흐름에 영상 변환, 음량 보정, 자막 번인, 보고서 기록이 포함돼 있었습니다. Python, Docker 실행 경로 제거와 서버, 공유 모듈의 역할별 폴더 정리도 로컬 Git 이력에서 확인했어요.

다만 역할별 폴더 정리는 같은 저장소 안의 모듈 경계를 정리한 작업입니다. 프론트엔드 저장소를 따로 만든 결과는 아니었어요. 당시 답변에는 타입 검사 통과가 기록돼 있지만 실제 미디어 제작과 화면, 청취 검수는 다시 실행하지 않았습니다. NAS, Google Drive 연동도 향후 범위로 남아 있었어요. 과거에 반영된 변경을 이날 새로 구현한 성과로 옮겨 적지는 않았습니다.

## Q. Tokens Studio 관련해서 참고한 글과 어긋나는 부분이 있으면 블로그 글을 수정해 주세요.

A. [디자인 시스템 글](/posts/design-system)의 토큰 변환 결과와 자동화 범위에 대한 설명을 수정했어요. 기존의 CSS 변수 출력, 수동 변환 설명을, Token Transformer가 참조를 해석한 JSON을 만들고 이를 Emotion에서 사용하는 흐름으로 정리했습니다.

자동화 설명도 GitHub Actions가 변환과 PR 생성을 수행하고, 변경 사항은 검토 후 머지하는 흐름으로 고쳤어요. PR 생성까지의 자동화와 제품 반영을 나눠 설명한 수정입니다. 이 기록에서 확인한 것은 당시의 글 수정 대화와 로컬 Git diff이며, 실제 디자인 토큰 변경을 보내 CI 실행이나 제품 반영까지 다시 검증한 것은 아닙니다.

## Q. 우선 서버 저장소와 프론트 저장소를 나누는 계획을 세워 주세요.

A. 기존 화면과 API 형식을 유지하면서 독립적으로 빌드하고, Mac 서버가 프론트 배포 파일을 제공하는 데 첫 범위를 두었어요. 처음에는 공유 모듈의 생성된 복사본을 검토했지만, 뒤의 실제 사용처 조사에서는 API 경계에서 의존성을 줄이는 방향으로 다시 제안했습니다. 초기 제안과 후속 검토를 하나의 확정 설계나 분리 완료로 합치지는 않았어요.

## Q. Python은 제거했는데 왜 Python 호환 JSON 처리가 남아 있나요?

A. 예전 데이터 형식을 보존하는 TypeScript 코드가 남아 있던 것이었어요. 런타임 제거와 데이터 형식 전환은 다른 작업입니다. 당시 분석에서는 무한대 같은 특수 측정값이 표준 JSON에서 그대로 표현되지 않고, 단순 직렬화 시 null로 바뀔 수 있다는 점을 확인했어요. HTTP 응답을 표준화하는 일과 기존 저장 기록, 해시의 호환성 처리를 나누자는 제안이었습니다.

## Q. 공통 모듈은 왜 공유하고, 반드시 같은 소스를 관리해야 하나요?

A. 실제 사용처를 보니 작은 구현 헬퍼, 통신 형식, 화면에 보여 줄 규칙 데이터가 섞여 있었어요. 같은 데이터를 표시해야 한다고 반드시 같은 소스 패키지나 복사본이 필요한 것은 아닙니다. 제작 규칙은 서버가 소유하고 프론트는 필요한 데이터를 API로 받으며, 각 저장소는 필요한 작은 헬퍼를 소유하는 방향을 제안했어요. 공통 폴더 안의 모든 파일이 양쪽에서 사용되는 것도 아니었습니다.

## Q. Intl은 무엇이고, 외부 언어 코드 라이브러리와 어떤 차이가 있나요?

A. `Intl`은 JavaScript에 내장된 국제화 기능으로 언어, 지역에 맞는 날짜, 숫자, 언어 이름 등을 다룹니다. 당시에는 언어 태그 정규화와 이름 표시에 내장 기능을 쓰고, 파일명 별칭 같은 앱 규칙은 서버에 남기는 조합을 제안했어요. 형식이 맞는 태그를 처리하는 것과 실제 ISO 코드의 유효성을 검증하는 것은 다르며, 내장 데이터는 실행 환경의 ICU 버전에 영향을 받습니다. 완전한 목록, 검증이나 데이터 버전 고정이 필요하면 외부 라이브러리와 다시 비교해야 해요.

## Q. 이 기록은 어떤 대화를 바탕으로 했나요?

A. 한국 시간 11월 2일 오전 10시 11분의 미디어 제작 도구 진행 상태 질문과 오후 1시 10분의 Tokens Studio 설명 정정 요청, 각각의 답변을 로컬 대화 파일에서 확인했습니다. 미디어 도구의 실행 경로 제거, 폴더 정리 이력과 블로그의 토큰 연동 설명 수정 커밋도 대조했어요. 날짜는 실제 질문 시각을 기준으로 정했으며, 새로 수행한 구현, 제작, CI 검증으로 확대하지 않았습니다. 외부 참고 글을 이번 작업에서 다시 조회하지 않았고, 계정 정보, 내부 경로, 로그 원문은 옮기지 않았어요.

11월 2일에 같은 날짜의 로컬 메시지 기록을 추가 대조해 누락된 개발 질문을 보완했습니다. 추가 내용은 당시 답변의 요약이며, 이번 작업에서 제품 동작을 다시 실행한 결과는 아닙니다.
