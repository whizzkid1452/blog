### 1. 개요 및 배경 (Context)

- Electron 앱을 오래 켰을 때 메모리가 누적되는지 살피기 위한 첫 확인으로, 실제 앱의 **로그인 대기 화면**을 측정함.
- 아무 작업도 하지 않는 상태를 먼저 보면 앱이 유휴 상태에서 유지하는 기본 수준을 관찰할 수 있음. 리전 편집과 음성 생성 중에 할당되는 자원은 별도 시나리오가 필요함.

### 2. 핵심 내용 / 문제 해결 과정 (Core / Troubleshooting)

- **Apple M4, RAM 32GB, macOS**에서 로그인 화면을 3분간 유지하며 19회 표본을 기록함. 아래 결과는 같은 실행에서 시작값과 종료값을 비교한 것임.

| 지표                    |      시작 |    3분 뒤 |
| ----------------------- | --------: | --------: |
| 앱 프로세스 메모리 합계 | 615.6 MiB | 592.9 MiB |
| Main JavaScript 힙      |  16.7 MiB |  14.7 MiB |
| Renderer JavaScript 힙  |  23.2 MiB |  14.9 MiB |

- 이번 대기 구간에서는 지속적인 증가가 관찰되지 않았음. 강제 종료 보고서에는 최근 메모리 표본 **7개**가 포함돼 있었음. 프로세스 메모리 합계에는 프로세스들이 공유하는 페이지가 중복될 수 있음.
- 전체 프로세스 합계는 앱이 유지하는 메모리의 큰 흐름을 파악하기 쉽고, 프로세스별 힙은 JavaScript 객체 관점에서 범위를 좁히는 데 적합함. 둘 다 높아지거나 한쪽만 변할 수 있으므로 같은 원인으로 해석하기 전에 함께 확인함.

### 3. 인사이트 및 적용점 (Takeaway & Next Action)

- **19회는 한 대기 구간의 표본 수**임. 독립 실행을 19번 반복한 결과로 해석하거나 영상 편집 및 장시간 누수의 결론으로 확장할 수 없음.
- 이후 편집 부하를 보려면 같은 프로젝트에서 열기, 편집, 닫기를 반복하고 각 작업 직후와 안정화 뒤의 프로세스별 수치를 대조하는 것이 적합함.
